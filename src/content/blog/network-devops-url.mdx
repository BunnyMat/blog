## مطالب مرتبط با دواپس
توی این بخش تمام مطالبی و مفاهیمی که از دواپس یادگرفتم رو پوشش میدم. از دپلوی گرفته تا ابزار های CI/CD و خیلی چیزای دیگه!👨‍💻
### مفهوم دپلوی
قبل از اینکه دریافت خودم رو از مفهوم دپلوی(Deploy) بگم، بیاین یه نگاهی به تعریف GPT از این مفهوم بندازیم.

> **دپلوی:** منتشر کردن پروژه روی یک محیط قابل دسترسی، معمولاً اینترنت.

**تعریف خودم از دپلوی**

به زبان ساده، دپلوی یعنی پروژه ای رو که روی سیستم شخصی خودت ساختی و نگهداری میکنی و اون رو به صورت local اجرا میکنی، حالا بیای و اون رو روی یک سرور یا یک سرویس هاستینگ قرار بدی، تا همه بتونن به اون دسترسی داشته باشن.

مثلا شما یک پروژه با ReactJS دارین و برای ران کردن اون از `npm run dev` استفاده میکنین و با همچین آدرسی میتونین به صورت لوکال روی کامپیوتر خودتون به پروژه دسترسی داشته باشین: `localhost:5173`

اما بنظرتون بقیه میتونن با این آدرس به پروژه ی شما دسترسی داشته باشن؟! مسلما نه. حتی شما اگه خوتونم ترمینال رو ببندین باید با پروژه خدافظی کنین.😁

پس راه حل چیه که همه بتونن به صورت آنلاین و 24/7 به پروژه شما دسترسی داشته باشن؟ باید پروژه خودتون رو روی یک سرور و یا سرویس هاستینگ دپلوی کنین!😃

### دپلوی روی سرویس های هاستینگ و لینوکس سرور

1. دپلوی روی سرویس های هاستینگ

یکی از ساده‌ترین روش‌های Deploy کردن پروژه، استفاده از سرویس‌های Hosting هست. سرویس‌هایی مثل Vercel، Cloudflare Pages و GitHub Pages خیلی از کارهای مربوط به Server رو خودشون انجام میدن. معمولاً پروژه رو به سرویس وصل می‌کنیم و بعد از هر تغییر، پروژه Build و Deploy میشه و یک آدرس برای دسترسی به اون در اختیارمون قرار می‌گیره.

یه مثال از Github Pages میزنم که کانسپتش دستتون بیاد.
تصور کنین که یه وبسایت با HTML, CSS و جاوااسکریپت ساختین.
یک ریپازیتوری گیتهاب میسازین و فایل های پروژه رو در اون قرار میدین و مراحل زیر رو دنبال میکنین.

وارد تب Settings میشین, تب Pages, Source رو روی main Branch و /root قرار میدیم و Save روی Save کلیک میکنیم.
و بوم! پروژه شما دپلوی شده و الان آنلاینه. 

اما چجوری بهش دسترسی داشته باشیم؟! برای مثال یوزرنیم من در گیتهاب `BunnyMat` و ریپو من `Website` هستش. 
لینک پیجز همچین چیزی خواهد شد.

https://BunnyMat.github.io/Website/
